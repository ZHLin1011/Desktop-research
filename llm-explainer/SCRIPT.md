# 脚本：《为什么大模型说话有快有慢》

**角色：** 呱基（小青蛙科普主播）  
**受众：** 对 AI 感兴趣的成年人（老师、传统行业、大学生等非 AI 从业者）

## 口播全文

### 1. 引出问题
**画面：** 呱基看手机：左边「秒回」，右边「转圈等待」  
**字幕/口播：**  
呱基。你有没有发现：有时候大模型几乎秒回，有时候却转圈转半天？今天把原因讲清楚。呱基。

### 2. 两段式总览
**画面：** 流程图「① 读题 Prefill → ② 写字 Decode」  
**字幕/口播：**  
呱基。大模型每次回答，其实分两段活：先「读题」，再「写字」。专业说法叫 Prefill 和 Decode。呱基。

### 3. Prefill（预填充）
**画面：** 呱基当老师，一次把整张试卷吞进脑子；旁边标 Prefill  
**类比：** 老师答题前先把整道题读完、理清条件——不是边读边写。  
**字幕/口播：**  
呱基。Prefill，就像老师先把整道题一次性读完。你贴的提示词、文件、聊天记录越长，这一步越吃力，开头就越容易卡住。呱基。

### 4. Decode（解码）
**画面：** 打字机/接龙：吐一个字，再猜下一个；进度条「字/秒」  
**类比：** 不是一次性交整篇作文，而是一个字一个字往外蹦。  
**字幕/口播：**  
呱基。Decode，是真正「说话」：模型一个字一个字往外蹦。你要它写长文、写代码，字数越多，等的时间就越长。呱基。

### 5. 影响因素
**画面：** 四个旋钮：输入长度、输出长度、模型大小、服务器排队  
**字幕/口播：**  
呱基。速度还受这些影响：输入越长 Prefill 越慢；输出越长 Decode 越久；模型越大通常越慢；高峰排队也会拖时间。呱基。

### 6. 实操干货
**画面：** 清单 checklist，呱基打勾  
**字幕/口播：**  
呱基。想少等待，记五条：少贴整份长文，先摘要再问；一次只问一个问题；写明「用三点回答」「一百字内」；长任务拆成多轮；日常聊天用轻量模型，重活再上大模型。呱基。

### 7. 收尾
**画面：** 呱基挥手 + 公式卡片  
**字幕/口播：**  
呱基。一句话：卡住多半在读题，写得慢多半在吐字。会拆任务，就能少干等。我们下期见。呱基。

## 知识点备忘（给创作者）

| 术语 | 一句话 | 类比 |
|------|--------|------|
| Prefill | 把整段输入并行算完，建立上下文 | 老师先通读题目 |
| Decode | 自回归逐 token 生成 | 打字机一个字一个字蹦 |
| TTFT | 首字延迟，常被 Prefill + 排队拉长 | 「开始说话」前的等待 |
| tokens/s | 生成速度 | 说话快慢 |

## 干货清单（可单独做成卡片）

- [ ] 一次一个问题  
- [ ] 限制输出长度（字数 / 条数 / 格式）  
- [ ] 复杂任务拆多轮  
- [ ] 轻活用小模型，重活用大模型
