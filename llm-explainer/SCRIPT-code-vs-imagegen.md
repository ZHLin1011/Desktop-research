## 旁白

**01 · 70 万笔**
嗨，我是呱基。
最近 Claude Fable 5.2 刷屏了，有人用它做视频、做 3D 动画，甚至写游戏。
最让人意外的是画画：它没有调用任何生图模型，每一幅画，都是一个一两千行的 Python 程序。
程序里模拟了颜料和不同的刷毛，每一笔都要先过一遍这个引擎，再落到画布上。
最写实的一张，整整画了七十万笔，放大看，全是笔触。
同样是 AI 画画，更常见的是生图模型：一句话，几秒出一张图。
这两条路，到底差在哪？

**02 · 写代码画**
先看写代码画画。模型并不是“看着”画布动笔，而是写下一条条指令。
画在哪、画什么、多大、什么颜色，全都写成数字，程序照着执行，一行就是一笔。
想画得更细，就把指令放进循环：一笔变一万笔、七十万笔，只是多算一会儿。
所以它交出来的，其实是一份图纸：每一笔都有据可查，改一个数字，就只改那一处。
而且放大多少倍，线条都清清楚楚。

**03 · 生图模型**
再看生图模型。它看过几十亿张图片和配套的文字，学会了什么样的话，对应什么样的画面。
你给一句话，比如“窗台上晒太阳的橘猫”，它先铺满一片随机的雪花点；
然后一步步去掉噪点，每一步都往你描述的样子靠近一点，二三十步后，整张图一起显影。
它交出来的是一张照片：一百来万个彩色小点，光影、质感都很逼真，几秒就好。

**04 · 改图**
真正拉开差距的，是修改。比如：把背景从蓝色换成绿色。
代码这边，改一个词，重新运行，房子和太阳纹丝不动，只有背景变了。
生图这边，往往要重新生成：背景是绿了，猫的姿势、窗户的样子，也可能跟着变。
写字也一样：海报上的“妈妈生日快乐”，代码一字不差；
生图模型这两年进步很大，可字一多、排版一精细，还是容易写错。

**05 · 要逼真**
反过来，如果要一张像照片的图：毛茸茸的猫、雨夜的霓虹、皮肤的质感，
代码就得把每一根毛、每一道光都算出来，那张写实画，用了上千行程序、七十万笔；
生图模型，几秒钟就能给你。
要质感、要氛围、要快，生图模型更合适。

**06 · 该用谁**
放到生活里，看看该用谁。
做数据图表、流程图、Logo 和图标，要精确、要反复改：用代码。
给笔记配一张氛围图、做个风格头像、出一张产品场景图：用生图。
做生日海报，可以两个一起上：生图画背景，代码把文字和日期一个不差地排上去。

**07 · 记住**
写代码画画，是一笔一笔下指令：准确、能改、放大不糊。
生图模型，是从雪花里一下显影：逼真、省事、出图快。
要准、要改、要写字，找代码；要像、要快、要氛围，找生图。
对了，你正在看的这支视频，每一根线条，也是代码一笔一笔画出来的。
我是呱基，我们下期见。
