## 旁白

**01 · 模型 Infra**
嗨，我是呱基。
你问 AI 一个问题，比如：帮我排一个周末出游计划。
几秒钟后，它就开始一个字一个字地回答你。
你看到的是模型，可在它背后，还有一整套让它跑起来的系统。
这套系统，就叫模型 Infra。Infra 是英文 infrastructure 的缩写，意思是基础设施。
打个比方：模型是大厨，Infra 就是让这位大厨，同时给几亿人做饭的整个后厨。

**02 · 底座**
先看最底层：一张张 GPU 显卡，装进机柜，几百个机柜，排成一整座机房。
训练一个顶级模型，要上万张卡一起算。Meta 训练 Llama 3，就用了一万六千多张卡，连续算了五十多天。
卡和卡之间要不停地交换数据，所以要专门的高速网络，比家里的宽带快几百倍。
光是这些卡，就要一万多千瓦的电。供电、散热，也都是 Infra 要管的事。

**03 · 训练**
大模型，一张卡根本装不下：四千亿个参数，光存下来就要八百多 GB，而一张卡只有八十 GB。
所以 Infra 要把活拆开：模型切成好几段，分到不同的卡上；
训练数据也分成很多份，每组卡各学一份，学完再对一对答案，合成同一份进度。
上万张卡一起跑，总会有卡出问题。Llama 3 那五十多天里，训练中断了四百多次，平均不到三个小时一次。
所以要定时存档，像打游戏存进度：哪张卡坏了就换掉，从最近的存档接着跑，不用从头再来。

**04 · 推理**
训练好了，模型要上线给你用，这一步叫推理服务。
你按下发送，请求先到入口排队；调度系统再找一台空闲、又装着这个模型的机器。
模型每算出一个字，就马上推回你的屏幕，所以你看到的是一个字一个字往外蹦。
同一时刻，可能有几百万人在问。高峰来了自动加机器，半夜人少再撤下来，省钱。

**05 · 省钱提速**
Infra 最见功力的地方，是让同样的卡，服务更多的人。
第一招，拼锅。模型每写一个字，都要把全部参数从显存里读一遍，就像每炒一次菜都要热一遍锅；
把几十个人的请求放进同一锅，读一遍参数，几十个人各得一个字。
第二招，备菜。聊了很久的对话，算过的部分先存起来，下一句不用从头再算；很多厂商对这部分，只收一成到一半的钱。
第三招，压缩。把模型压小一些，同样的卡装得下、跑得快。

**06 · 和你有关**
那 Infra 跟你有什么关系？它决定了你用 AI 的三种感受。
快不快：第一个字多久出来，后面的字蹦得多快；
稳不稳：高峰期，会不会弹出一句“服务繁忙，请稍后再试”；
贵不贵：同样水平的模型，价格大约每年降到原来的十分之一，这里面，有不少是 Infra 的功劳。

**07 · 记住**
记住这个比方：模型是大厨，Infra 是后厨。
灶台是 GPU，传菜靠高速网络，排单靠调度；拼锅、备菜省时省钱，还得随时存档、坏了就换。
下次 AI 回得又快又便宜，别忘了水面下的那一大块。
我是呱基，我们下期见。

## 数字依据

| 说法 | 依据 |
|------|------|
| Llama 3 用了一万六千多张卡 | Meta《The Llama 3 Herd of Models》（2024）：405B 模型在最多 16,384 张 H100 上训练 |
| 连续五十多天、中断四百多次、平均不到三小时一次 | 同上：54 天快照期内 466 次作业中断（419 次意外），约 78% 归因硬件；54×24÷466 ≈ 2.8 小时 |
| 一万多千瓦 | H100 SXM 单卡 TDP 约 700 W；16,384 × 700 W ≈ 11.5 MW（不含 CPU、网络、制冷） |
| 比家用宽带快几百倍 | 训练集群单卡常配 400 Gb/s InfiniBand / RoCE 网卡；家用宽带 100 Mb/s–1 Gb/s |
| 四千亿参数要八百多 GB，一张卡 80 GB | 405B × 2 字节（BF16）≈ 810 GB；H100 显存 80 GB（训练时还要再加优化器状态，需求更大） |
| 模型切段、数据分份、对答案 | 张量 / 流水线并行（切模型）+ 数据并行（切数据，梯度同步） |
| 每写一个字都要把参数读一遍 | 自回归解码每步需读取全部权重，显存带宽是瓶颈；批处理让一次读取服务多个请求（vLLM 等连续批处理吞吐提升数倍） |
| 缓存部分只收一成到一半 | 主流 API 的提示词缓存命中价：约为原价的 10%–50%（各家不同） |
| 同水平模型价格每年约降到 1/10 | a16z「LLMflation」（2024）：同等能力的 LLM 推理成本约每年下降 10 倍 |
| 几百万人同时在问 | 头部 AI 助手周活以亿计，高峰并发以百万计（口播取“可能有几百万人”） |
